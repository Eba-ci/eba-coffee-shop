# Serveur MCP (gestion de l'application)

> Déplacé de CLAUDE.md. Doc des outils : `app/api/mcp/README.md`.


- **Endpoint** : `POST /api/mcp` — serveur [MCP](https://modelcontextprotocol.io) distant (transport Streamable HTTP, JSON-RPC 2.0, sans état) **d'administration de l'app** à destination d'un client comme Claude. Il expose : la gestion du menu (lecture + écriture), les statistiques en lecture seule (`get_daily_stats`, `get_range_stats`, `get_daily_series`, `get_top_products`, branchés sur `lib/stats.ts` ; `get_product_stats` — ventes d'UN produit : unités, CA, coût figé sur les lignes, marge, part du CA, rang, série journalière et suppléments les plus choisis — branché sur `lib/product-stats.ts`), la gestion **complète des dépenses** (catégories + dépenses, lecture **et** écriture : `list_expense_categories`, `create/update/delete_expense_category`, `list_expenses`, `get_expense_summary`, `create/update/delete_expense`, `set_expense_receipt`, branchés sur `lib/expenses.ts` + `lib/expense-mutations.ts`), la gestion **complète des investissements** (apports/financements : sources + apports, lecture **et** écriture : `list_investment_sources`, `create/update/delete_investment_source`, `list_investments`, `get_investment_summary`, `create/update/delete_investment`, `set_investment_document`, branchés sur `lib/investments.ts` + `lib/investment-mutations.ts`), les **régularisations de recette** (ajustement manuel du CA sans commande : `list_revenue_adjustments`, `get_revenue_adjustment_summary`, `create/update/delete_revenue_adjustment`, branchés sur `lib/revenue-adjustments.ts` + `lib/revenue-adjustment-mutations.ts` ; injectées dans `lib/stats.ts`), la **clôture de caisse** (espèces, journalière : `get_cash_position`, `get_cash_closing`, `list_cash_closings`, `save_cash_closing`, branchés sur `lib/cash-closing.ts` + `lib/cash-closing-mutations.ts`), les **clients/CRM en lecture** (`list_customers`, `get_customer`, branchés sur `lib/customers.ts`), l'**ardoise en lecture** (dette réelle : commandes **récupérées et non payées**, regroupées par client, toutes dates confondues et sans borne — plus une liste `toCheck` des impayées anciennes jamais marquées récupérées, **hors total** : `get_ardoise`, branché sur `lib/ardoise.ts`), et la **fidélité** (carte à tampons : `get_loyalty_card`, `adjust_loyalty_stamps`, `get/update_loyalty_settings`, branchés sur `lib/loyalty.ts` + `lib/loyalty-mutations.ts` + `lib/loyalty-settings-db.ts`), et la **gestion d'inventaire périodique** (matières premières & consommables, lecture **et** écriture : références, réappro/achats avec PMP, comptages, annulation de lot, réglages : `list_inventory_items`, `get_inventory_item`, `get_inventory_summary`, `list_low_stock_items`, `list_inventory_purchases`, `list_inventory_counts`, `get_inventory_count`, `create/update/archive_inventory_item`, `record_inventory_purchases`, `cancel_restock_batch`, `record_inventory_count`, `get/update_inventory_settings`, branchés sur `lib/inventory.ts` + `lib/inventory-mutations.ts` + `lib/inventory-settings-db.ts`), et les **sondages** (moteur générique de vote, lecture **et** écriture : sondages + options + modération des suggestions de la communauté : `list_polls`, `get_poll`, `get_poll_results`, `create/update/delete_poll`, `set_poll_status`, `set_poll_image`, `create/update/move/delete_poll_option`, `set_poll_option_image`, `list_poll_suggestions`, `get_poll_suggestion`, `moderate_poll_suggestion`, branchés sur `lib/polls.ts` + `lib/poll-mutations.ts`), et les **coordonnées du commerce** (adresse, horaires, téléphone, WhatsApp Business, email, liens Maps, réseaux sociaux, lecture **et** écriture : `get_contact_settings`, `update_contact_settings`, branchés sur `lib/contact-settings.ts` + `lib/contact-settings-db.ts`). Doc complète : `app/api/mcp/README.md`.

- **Auth** : deux modes (la route tente la clé statique, **puis** OAuth). (1) **OAuth 2.0** — plugin `mcp` de Better Auth (`lib/auth.ts`), pour Claude **web/mobile/desktop** : l'utilisateur se connecte avec son compte et **seuls les rôles ADMIN, MANAGER, COMPTABLE et ANALYSTE sont autorisés** (401 si non connecté ; 403 si connecté avec un autre rôle). `ADMIN` a accès à tous les outils ; `MANAGER` à tous **sauf** les outils `scope: 'admin'` (le détail des salaires reste à l'ADMIN) ; `COMPTABLE` est restreint aux outils finance (dépenses, investissements, régularisations, clôture de caisse, stats — cf. `FINANCE_TOOL_NAMES` dans `lib/mcp/tools/registry.ts`) ; `ANALYSTE` est restreint aux outils en **lecture seule**, tous domaines confondus (cf. `READ_ONLY_TOOL_NAMES` dans `lib/mcp/tools/registry.ts`). Découverte exposée à la racine de l'origine (`app/.well-known/{oauth-authorization-server,openid-configuration,oauth-protected-resource}` + variantes `…/api/mcp` avec chemin de ressource inséré), en GET **et** OPTIONS (préflight CORS — helper partagé `lib/mcp/cors.ts`, appliqué aussi aux chemins `/api/auth/.well-known/*` + `/api/auth/mcp/*` par le catch-all) ; endpoints OAuth sous `/api/auth/mcp/*` (dont l'enregistrement dynamique de client RFC 7591 : `POST /api/auth/mcp/register`) ; `BETTER_AUTH_URL` sert d'`issuer`. La page `/login` **reprend** le flux OAuth après connexion. Tables Prisma : `OauthApplication`/`OauthAccessToken`/`OauthConsent` (lancer `pnpm db:push` après déploiement). (2) **Clé statique** `MCP_API_KEY` en `Authorization: Bearer <token>` (comparaison à temps constant) — **optionnelle**, pour les clients « machine » (CLI/curl) ; si absente, seul OAuth reste actif. **La clé statique n'a pas le scope `admin`** : le détail des salaires exige un compte ADMIN identifié par OAuth.

- **Architecture** : `app/api/mcp/route.ts` (mince : POST/GET/OPTIONS) → `lib/mcp/http/` (transport : clé statique, garde-fou de rôle ADMIN/MANAGER/COMPTABLE/ANALYSTE, `?toolset=`, flux SSE, revalidation cache) → `lib/mcp/handler.ts` (dispatch JSON-RPC, agnostique du framework, filtre `tools/list`/`tools/call` par `allowedTools`) → `lib/mcp/tools.ts` (barrel) → `lib/mcp/tools/registry.ts` (registre assemblant un module `McpTool[]` par domaine dans `lib/mcp/tools/`).

- **Règle d'or** : les outils MCP ne dupliquent **aucune** logique métier. Ils branchent `lib/menu.ts` (`getMenuAdmin`) et `lib/menu-mutations.ts`, et réutilisent les schémas Zod existants (`z.toJSONSchema` génère le `inputSchema`). Pour ajouter un outil, étends le module de son domaine dans `lib/mcp/tools/` ; pour un nouveau domaine, crée un module `McpTool[]` **et** ajoute son spread dans `registry.ts` (sinon l'outil est absent de `tools/list`, des gardes de rôle et du filtre `?toolset=`).

- **Images** : la persistance vit dans `lib/uploads.ts` (`saveImage`), partagée par les routes `/api/upload` + `/api/upload/receipt` (multipart, dashboard) et les outils MCP `set_product_image` / `set_expense_receipt` / `set_investment_document` (base64). Toute image reçue (JPEG/PNG/WebP/AVIF/HEIC, max 25 MB — `MAX_UPLOAD_SIZE_BYTES`) est **retraitée avec `sharp`** : auto-orientation EXIF, redimensionnement « inside » `IMAGE_MAX_DIMENSION` (2200 px), ré-encodage **WebP** (`IMAGE_WEBP_QUALITY`), puis écrite en `/uploads/<subdir>/<uuid>.webp`. Les formats/tailles autorisés sont centralisés dans `lib/schemas/upload.ts` (`ALLOWED_IMAGE_MIME_TYPES`, qui ré-exporte `MAX_UPLOAD_SIZE_BYTES` depuis `config/constants.ts`). `imageUrlSchema` accepte un chemin relatif `/uploads/...` **ou** une URL http(s). `update_product` est une mise à jour **partielle** (champs absents = inchangés).

- **Outils en lot** : `bulk_update_products` et `bulk_set_product_stock` (`lib/menu/mutations/bulk.ts`, plafond `BULK_PRODUCTS_MAX`) modifient jusqu'à 100 produits en une transaction : validation complète avant écriture (un id inconnu → rien n'est écrit), `dryRun` pour l'aperçu, **valeurs absolues uniquement** (jamais de `toggle_*`/`restock_*` en lot : un rejeu doublerait l'effet). Une écriture de masse ailleurs suit le même patron ; ne jamais mettre en lot suppression, encaissement, remboursement ni fidélité. `pendingLabel` (`lib/ai/assistant/labels.ts`) libelle ces lots sur la carte de confirmation.
